# Read-only assessment

I inspected package.json, cordis.patch.yml, patch.yml, scripts/apply-patch.mjs and src/index.ts. All seven categories have hits. This is a static assessment, not an executed migration.

1. Source patch: patch.yml:3 targets `src/session/view/SessionView.ts`, cordis.patch.yml:5-6 includes that patch, and scripts/apply-patch.mjs:8 reads it. This couples the plugin to private session-view source. A1-03 requires checking each target against the target tag, preferably migrating to public facets rather than guessing replacement internal paths.
2. Events: src/index.ts:15-21 emits `legacy/informational-note` with `ignorable: true` and subscribes to session/event. A1-02 removed that marker temporarily; A2-01 restored omission-safe informational-event semantics. Preserve such existing markers in producer/persistence envelopes. Do not whitelist required unknown events. This restoration does not prove that an ordinary plugin can persist arbitrary custom events through Session.append; its supported writer API still needs checking.
3. Host service: src/index.ts:26-31 gets apiProxy and invokes session.rename and llm.providers. A1-01 removes APIProxy. Host code should inject the corresponding actual domain services, for example llm and ctx.llm.listProviders(); Web Client calls use the appropriate Remote surface. The exact session-renaming seam needs target exports, rather than blindly injecting remote on the Host.
4. Host filesystem: src/index.ts:36 builds a path from homedir(), .dsh, profiles and default. A1-04 calls for runtime DSH_HOME and the selected profile/composition as the source of truth. --profile already existed before alpha.1.
5. UI/commands: src/index.ts:10 imports SessionView from an internal package path, and src/index.ts:41-43 registers a command that constructs it. A1-03's split invalidates these private couplings; identify target-owned public facets and verify both registration and rendering.
6. Custom channel: src/index.ts:48-51 creates a private loopback HTTP server. A1-08 means loopback is not an authentication exemption: use host-managed connection channels and their auth integration. Bootstrap-token and signed-cookie handling for Web/API does not automatically protect a raw createServer route.
7. Subprocess/output: src/index.ts:59-63 spawns dsh and JSON-parses stdout; scripts/apply-patch.mjs:12-18 makes the same assumption. A1-04 covers profile/launcher assumptions and A1-05 describes stderr progress versus final-text stdout. JSONL parsing was already wrong before alpha.2. Consume final text, handle stderr progress separately and check process exit status.

The mapping is A1-03 for source/UI, A1-02 plus A2-01 for events, A1-01 for services, A1-04 for filesystem/launcher, A1-08 for custom channels, with A1-05 additionally clarifying output. There are no no-hit categories, but this does not prove dependency/config/runtime compatibility. After migration, perform build/typecheck, an isolated alpha.2 profile cold boot without pending, and a core functional call. Do not execute this deliberately static fixture.
