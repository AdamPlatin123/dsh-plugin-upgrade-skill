# Snapshot migration assessment

The changes below are located in src/client/Pet.tsx, src/client/index.ts and package.json. I have not executed the static plugin or changed its files.

In src/client/Pet.tsx:14,21,23 the animation reads partial, runningCalls and turnEnds from the old flat ConversationSnapshot. DSH-0.1.2-A1-03 describes the temporary chat compatibility projection through views.get('chat')?.legacy. First preserve these field semantics through that projection; subsequently migrate chat content and turn history to the target-owned views/timeline surfaces. A supported direct Chat migration can also work, but it must preserve ordering rather than assume the old array shape.

src/client/Pet.tsx:19 reads running through useSession. Running remains Session lifecycle state, outside the chat legacy projection; keep it on the Session/useSession seat while separating the chat-derived reads. Merely renaming every useSession call to a Chat hook would be wrong.

src/client/index.ts:6 and src/client/Pet.tsx:8 import from the removed dsh-client-runtime. Context becomes `import type { Context as ClientContext } from '@deepseek-ai/cordis'`; the ConversationSnapshot replacement must come from its actual target domain owner, not an invented cordis export. I would verify the exact snapshot type in target exports. package.json:8 also declares dsh-client-runtime in client.inject; remove the phantom package and retain only real target providers. A1-25 additionally documents the package removal; type erasure does not repair unresolved type imports.

src/client/index.ts:38-42 uses scope.slots.register for conversation.session.header.actions. Under DSH-0.1.2-A1-03, migrate to the supported slots.inject(name, () => slots.register(...)) lifecycle, retaining the slot and component and checking disposal. Add the @deepseek-ai/dsh-client-ui-renderer/client type augmentation for the slots service; the existing locale and slot-name augmentations serve different owners.

The snapshot projection, Session lifecycle split and slot registration map to DSH-0.1.2-A1-03; package removal additionally maps to A1-25. The two-step compatibility path applies to partial/runningCalls/turnEnds. Type imports, the deleted inject entry and the split of lifecycle from chat reads need immediate attention. Once implemented, typecheck and actually mount the plugin against the target version.
