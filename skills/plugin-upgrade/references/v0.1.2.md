# DSH 0.1.1 → 0.1.2 完整迁移指南

> 基于 alpha.1 + alpha.2 整合，补充实战经验。
> 素材来源：官方 release notes + [discussion #5120](https://github.com/deepseek-ai/deepseek-harness/discussions/5120) 社区迁移实践 + 上游 Agent Notes。

## 概述

0.1.2 是一个大版本升级，包含多个破坏性变更。主要影响：
- SDK 包重组（2 个包被删除）
- APIProxy 完全移除，改用 `@Remote` 网关
- 模块表与平台模块机制变化
- Gateway 参数严格校验
- 启动和输出语义变更

**建议升级路径**：
1. 如果从 0.1.1-rc.2 升级，先过 alpha.1、alpha.2 两版卡片
2. 如果跨大版本升级，按本指南一次性迁移

---

## 破坏性变更清单

### BC-01 · SDK 包删除

**影响触点**: #3 内部服务探测、客户端导入

`@deepseek-ai/dsh-host-apiproxy` 和 `@deepseek-ai/dsh-client-runtime` 从 cohort 移除。

**客户端侧迁移映射**:

| 旧导入 | 新导入 |
|---|---|
| `@deepseek-ai/dsh-client-runtime/client` → `ClientContext` | `@deepseek-ai/cordis` → `Context`（类型别名） |
| `@deepseek-ai/dsh-client-runtime/client` → `useSettings` | `@deepseek-ai/dsh-client-ui-settings/client` |
| `@deepseek-ai/dsh-client-runtime/client` → store 引擎 | `@deepseek-ai/dsh-client-store` |
| `@deepseek-ai/dsh-client-runtime/client` → sessions | `@deepseek-ai/dsh-api-session-controller/client` |
| `@deepseek-ai/dsh-client-runtime/client` → workspaces | `@deepseek-ai/dsh-api-workspace-controller` |
| `@deepseek-ai/dsh-client-runtime/client` → `ctx.slots` | `@deepseek-ai/dsh-client-ui-renderer/client` |

**宿主侧迁移**:
- 删除所有 `dsh-host-apiproxy` 导入
- 注入 `TypertGateway`：`ctx.inject('typert.gateway')`
- Business 调用改为 `{ namespace, method, args: { request } }` 格式

**验证方法**:
```sh
# 检查残留引用
grep -r "dsh-host-apiproxy\|dsh-client-runtime" src/
# 构建验证
pnpm run build
# 类型检查
pnpm run typecheck
```

### BC-02 · APIProxy 完全移除 → `@Remote` 网关

**影响触点**: #3 内部服务探测

所有 APIProxy 操作迁移到 `ctx.remote.<namespace>.<method>()` 或 `TypertGateway.invoke()`。

**完整映射表**（17 条操作）:

| 旧 APIProxy 操作 | 新 Remote 方法 | 参数变化 |
|---|---|---|
| `session.rename` | `sessionTitle/rename` | 返回标题事件序列 |
| `command.list` | `commands/list` | 保留 Agent 查找 |
| `command.execute` | `commands/execute` | 保留取消权 |
| `llm.providers` | `llm/listProviders` + `llm/listConfigurableProviders` | **拆成两个方法** |
| `llm.discoverModels` | `llm/discoverModels` | 无变化 |
| `llm.models` | `session/modelCatalog` | **挪到 Session 域** |
| `credentials.describe` | `credentials/describe` | 无变化 |
| `credentials.set` | `credentials/set` | 无变化 |
| `credentials.unset` | `credentials/unset` | 无变化 |
| `settings.describe` | `settings/describe` | 保留脱敏 |
| `settings.update` | `settings/update` | 保留修订检查 |
| `settings.replace` | `settings/replace` | 保留修订检查 |
| `settings.mutate` | `settings/mutate` | 保留修订检查 |
| `settings.openDocument` | `settings/openSettingsDocument` | 无变化 |
| `agentPreset.read` | `agentPresets/read` | 无变化 |
| `agentPreset.copy` | `agentPresets/copy` | 无变化 |
| `agentPreset.remove` | `agentPresets/remove` | 无变化 |
| `agentPreset.openDocument` | `settings/openAgentPresetDirectory` | **域变化** |
| `subagent.interrupt` | `subagents/interruptByParent` | 保留父权威 |
| `workspace.list` | `workspace/list` | 无变化 |
| `workspace.insertSessionBefore` | `workspace/insertSessionBefore` | 无变化 |
| `workspace.archiveSession` | `workspace/archiveSession` | 无变化 |
| `skill.list` | `skills/list` | 列举不再激活 Agent |
| `fileReferences/list` | `fileReferences/list` | 无变化 |
| `host.openPath` | `session/openWorkspacePath` | Client 先解析相对路径 |
| `host.describe` | `$events` ready 帧 + 按页能力查询 | 改读 `ctx.remote.$host.home` |
| `session.export` | `GET/HEAD /api/session.export` | **走 Fetch 流式 ZIP** |

**迁移配方**:

```typescript
// 旧代码
import { executeRemote } from '@deepseek-ai/dsh-host-apiproxy'
const sessions = await executeRemote('session', 'list', { limit: 10 })

// 新代码
export class MyService {
  private gateway: any
  
  constructor(ctx: Context) {
    this.gateway = ctx.inject('typert.gateway')
  }
  
  async listSessions() {
    // 注意：参数名为 _request
    return this.gateway.invoke('session', 'list', {
      _request: { limit: 10 }
    })
  }
}
```

**验证方法**:
- 检查所有 API 调用返回预期结果
- 错误处理改用 `RemoteError`（见 BC-05）

### BC-04 · Gateway 描述符严格校验

**影响触点**: #3 内部服务探测

0.1.2 对 `TypertGateway` 调用执行 `assertExactArguments` 严格校验，必须按描述符有线布局组参。

**常见错误场景**:

| 调用 | 错误原因 | 正确写法 |
|---|---|---|
| `gateway.invoke('session', 'list', {request: {}})` | 参数名错误 | `{ _request: {} }` |
| `gateway.invoke('directoryPicker', 'list', {request: {path}})` | 嵌套错误 | `{ path }` |
| `gateway.invoke('session', 'follow', {})` | stream 方法用错 API | 改用 `gateway.stream()` |

**迁移配方**:

```typescript
// 创建描述符映射帮助函数
function invokeWireArgs(namespace: string, method: string, request: any) {
  const descriptors = {
    'session/list': { _request: request },
    'directoryPicker/list': { path: request.path },
    'agentPresets/list': {},
    'session/modelCatalog': {},
    // ...
  }
  const key = `${namespace}/${method}`
  return descriptors[key] ?? { request }
}

// 使用
await gateway.invoke('session', 'list', 
  invokeWireArgs('session', 'list', { limit: 10 }))

// stream 方法
const stream = await gateway.stream('session', 'follow', { sessionId })
```

**验证方法**:
- 运行时检查无 `arguments-invalid` 错误
- 测试 fakes 编码同一套描述符表

### BC-05 · RemoteError 封装与错误码

**影响触点**: #3 内部服务探测

业务失败以 `RemoteError` 携带错误码，与 `gateway/internal` 可区分。

**迁移配方**:

```typescript
// 旧代码
try {
  await apiProxy.call('session', 'get', { id })
} catch (error) {
  if (error.code === 'session/not-found') {
    // 处理
  }
}

// 新代码
try {
  await gateway.invoke('session', 'get', { _request: { id } })
} catch (error) {
  // RemoteError 直接携带 code
  if (error.code === 'session/not-found') {
    // 处理
  }
  // gateway/internal 只在未分类错误时出现
}
```

**常见错误码**:
- `session/not-found`
- `session/agent-busy`
- `service-unavailable`
- `arguments-invalid`

### BC-06 · 启动竞态与服务等待

**影响触点**: #3 内部服务探测

0.1.2 宿主 `sessionController` 需等待 9 个注入服务，但宿主 `start()` 立即发起首次 roster poll，导致 `service-unavailable`。

**迁移配方**:

```typescript
async function pollWithRetry(
  fn: () => Promise<any>, 
  maxRetries = 5
) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn()
    } catch (error) {
      if (error.code === 'service-unavailable' && i < maxRetries - 1) {
        await new Promise(resolve => 
          setTimeout(resolve, 2000 * (i + 1)))
        continue
      }
      throw error
    }
  }
}

// 使用
const sessions = await pollWithRetry(() => 
  gateway.invoke('session', 'list', { _request: {} }))
```

**注意**: 不要盲目延迟首 poll 或把 `sessionController` 加回 inject wait。

### BC-07 · 会话视图工程拆分

**影响触点**: #1 源码 patch、#5 UI 注册

"会话视图工程大幅拆分，请面向诉求分层导入合适模块"。

**影响**: patch 目标文件路径、内部导入路径可能失效。

**迁移方法**:
1. 逐一核对 patch 目标文件是否移动/拆分
2. 按新分层重导入模块
3. 更新 patch 路径映射

**验证**: 运行 patch 脚本，检查无文件未找到错误。

### BC-08 · Headless 输出语义变更

**影响触点**: #6 子进程 / stdout 解析

**变更**: Headless 模式下，进度流改走 stderr，stdout 只出最终结果。

**迁移配方**:

```typescript
// 旧代码
const result = execSync('dsh --headless "task"')
const output = result.toString() // 混合进度和结果

// 新代码
const result = execSync('dsh --headless "task"', {
  stdio: ['pipe', 'pipe', 'pipe']
})
const finalResult = result.stdout.toString() // 只有结果
const progress = result.stderr.toString() // 进度信息
```

**验证**: 解析 stdout 的包装器/脚本需要改为分别解析 stdout 和 stderr。

## 跨 cohort 共存（未发布版本）

**场景**: 插件必须同时在 0.1.1 和 0.1.2 宿主运行（preview cohort 未发布但插件已发布）。

### 方案-01 · Store 引擎双 cohort shim

```typescript
// shared/tsdown.client.ts
import { defineConfig } from 'tsdown'

export default defineConfig({
  external: (id) => {
    // 不 externalize，改为运行时探测
    if (id.includes('dsh-client-store') || id.includes('dsh-client-runtime')) {
      return false
    }
    return /^@deepseek-ai\/dsh-/.test(id)
  },
  banner: {
    js: `
// 双 cohort store 引擎探测
function resolveStoreEngine() {
  const newSpec = ['@deepseek-ai', 'dsh-client-store'].join('/')
  const oldSpec = ['@deepseek-ai', 'dsh-client-runtime', 'client'].join('/')
  try {
    return require(newSpec)
  } catch {
    return require(oldSpec)
  }
}
const { createStore, getSnapshot } = resolveStoreEngine()
export { createStore, getSnapshot }
    `
  }
})
```

**注意**: 只转共享值表面，cohort 独有导出（如 `notifySubscribers`）不能 re-export。

### 方案-02 · 注入服务探测

```typescript
export class MyService {
  private agentPresets: any

  constructor(ctx: Context) {
    // 0.1.2 新增，0.1.1 没有
    try {
      this.agentPresets = ctx.remote.agentPresets
    } catch {
      this.agentPresets = ctx.connection?.api?.agentPresets
    }
  }
}
```

**注意**: cordis `remote` 代理对未注入属性是 throw，必须 try/catch。

## 未发布 preview cohort 安装

**场景**: 从 0.1.1-rc.2 升级到 0.1.2-alpha.1（未发布到 npm）。

### 步骤-01 · 构建 tarball store

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git /tmp/dsh-build
cd /tmp/dsh-build
git checkout deepseek-harness@dsh-v0.1.2-alpha.1
pnpm install && pnpm run build
mkdir -p ~/.dsh-cohorts/0.1.2-alpha.1
pnpm -r exec pnpm pack --pack-destination ~/.dsh-cohorts/0.1.2-alpha.1
```

### 步骤-02 · 配置 overrides

```json
// package.json 或 pnpm-workspace.yaml
{
  "pnpm": {
    "overrides": {
      "@deepseek-ai/dsh-session": "file:/home/user/.dsh-cohorts/0.1.2-alpha.1/deepseek-ai-dsh-session-0.1.2-alpha.1.tgz",
      // ... 所有依赖包
    }
  },
  "packageManager": "pnpm@11.24.0"
}
```

**注意**: pnpm 11.9.0 对 file: tarball 解析有 bug，需升级到 11.24.0+。

### 步骤-03 · CI 适配

```javascript
// scripts/build-cohort-tarballs.mjs
import { readFileSync, existsSync } from 'fs'

const pkgJson = JSON.parse(readFileSync('package.json', 'utf-8'))
const overrides = pkgJson.pnpm?.overrides || {}

for (const [pkg, path] of Object.entries(overrides)) {
  if (path.startsWith('file:') && !existsSync(path.replace('file:', ''))) {
    // 重新构建
    break
  }
}
```

```yaml
# .github/workflows/ci.yml
- uses: pnpm/action-setup@v2
  # 删除 version，让 packageManager 决定

- name: Build cohort tarballs
  run: node scripts/build-cohort-tarballs.mjs

- uses: actions/cache@v3
  with:
    path: ~/.dsh-cohorts
    key: cohort-${{ hashFiles('package.json') }}
```
